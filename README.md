# 苏伊温德日历 · GitHub Pages 发布包

这是 **V1.3.2「固定设备长期登录修复」** 的 GitHub Pages 发布目录。

## V1.3.2

- 修复手机端偶发“明明登录过，过一阵又要求重新登录”的问题。
- Supabase 客户端改为**单实例初始化**，避免启动阶段多次创建客户端、并发刷新 refresh token。
- 新增 refresh token **并发锁**：同一时刻只允许一次登录续期请求，降低令牌轮换竞争导致会话被清空的风险。
- 登录状态默认持久化到本设备；只要不主动退出、不开启会清理站点数据的策略，打开日历会自动恢复账号。
- access token 临近过期时会自动续期；应用回到前台、重新聚焦或从后台恢复时，也会再次检查并恢复会话。
- 临时断网、Supabase 5xx/429 等服务异常时，**不再直接删除本地登录状态**；联网后可继续恢复。
- token 刷新后保留已有 user 信息，避免续期瞬间把界面误判成“未登录”。
- 云同步弹窗新增“正在恢复本设备登录”状态，减少启动时的假性掉登录提示。
- PWA 缓存升级为 `v132`，确保手机端能拿到新版本脚本。
- 不修改 `calendar_state` 表结构，不需要重新执行 Supabase SQL；原账号、云端数据、日历数据都继续沿用。

## 仍然会需要重新登录的情况

“长期登录”不是把密码或 JWT 永久有效化。以下情况仍会要求重新登录：

- 主动点击“退出”；
- 删除 PWA、清除浏览器/网站数据；
- Supabase 后台主动撤销会话或调整会话策略；
- refresh token 已经在旧版本中被清除/失效。

如果旧版已经把手机上的会话清掉，升级到 V1.3.2 后需要**再登录一次**；之后会按新的长期登录逻辑维护。
